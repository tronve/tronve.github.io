버그바운티는 기업이나 기관이 자신의 서비스에서 취약점을 찾아 제보한 사람에게 보상을 주는 제도다. 공부를 시작하기 전에, 실제 프로그램의 규칙을 하나 골라 꼼꼼히 읽어 보았다. HSPACE가 운영하는 버그바운티 프로그램(HVE, HSPACE Vulnerabilities and Exposures)이다.

## CTF와 무엇이 다른가

CTF와 워게임은 공격해도 되도록 만들어진 문제를 푸는 것이다. 버그바운티는 **실제로 운영 중인 서비스**를 대상으로 하고, **허락받은 범위 안에서만** 테스트해야 한다. 플래그를 찾는 것이 목표가 아니라, 취약점이 실제로 어떤 피해를 낼 수 있는지 증명하고 그 내용을 보고서로 전달하는 것까지가 일이다.

그래서 기술보다 먼저 규칙을 읽어야 한다고 생각했다.

## HSPACE HVE 프로그램 정리

### 범위

| 대상 | 설명 |
| --- | --- |
| `*.hspace.io` | 메인 서비스 (웹 애플리케이션) |
| `forge.hspace.io` | FORGE CTF 플랫폼 |

두 대상의 하위 경로와 API 엔드포인트가 모두 포함된다. 목록에 없는 HSPACE 서비스나 외부 연동 서비스는 범위 밖이다.

### 취약점으로 인정되지 않는 것

범위 밖 목록이 가장 인상 깊었다. 일부를 옮기면 다음과 같다.

- 자동화 스캐너 결과만 제출한 보고서
- 실제 공격 시나리오나 영향이 증명되지 않은 이론적 취약점
- 재현되지 않는 문제
- 실제 위협이 증명되지 않은 오래된 라이브러리 사용
- 보안 헤더(CSP, X-Frame-Options 등) 누락만 지적한 경우
- 접근할 수 없는 관리자 경로 노출
- 자기 계정에만 영향을 주는 Self-XSS
- Rate limiting 누락

이 목록이 거꾸로 "취약점이란 무엇인가"를 정의하고 있다고 느꼈다. **무언가 이상해 보이는 것**이 아니라, **실제 공격으로 이어져 피해를 낼 수 있다는 것을 증명한 것**이 취약점이다.

### 금지 행위

- 서비스 가용성에 영향을 주는 행위 (DoS, DDoS, 대량 트래픽)
- 다른 사용자의 데이터 열람, 변경, 삭제, 대량 추출
- 피싱 같은 사회공학 공격
- 물리적 공격
- 대량 자동 스캔
- 취약점을 악용해 실제 피해를 주는 행위
- 패치 전 제3자 공유나 외부 공개

검증 중에 접근한 데이터는 삭제해야 하고, 취약점은 HSPACE가 패치를 완료하고 알려 준 뒤에야 기술 분석을 공개할 수 있다. 책임 있는 공개(responsible disclosure)의 원칙이다.

### 보고서에 들어가야 하는 것

- 취약점 유형 (RCE, SQLi, XSS, IDOR 등)
- 정확한 URL 또는 엔드포인트
- 단계별 재현 방법 (스크린샷, 영상, 코드 권장)
- 공격 페이로드
- 테스트 환경 (OS, 브라우저, 도구 버전)
- 실제 피해를 설명하는 영향 분석
- 수정 제안 (선택이지만 평가에 반영)

심각도는 CVSS 점수와 실제 영향을 함께 고려해 Critical부터 Info까지 나뉘고, 보고서 품질이 보상에 직접 반영된다. 접수되면 `HVE-YYYY-NNNN` 형식의 번호가 붙고, 확인과 재현, 심각도 판정, 패치, 보상 순서로 처리된다.

## 읽으며 한 생각

보고서 항목을 보면서 화이트햇 스쿨 프로젝트의 교차 검증이 떠올랐다. 팀원끼리 서로의 스크립트를 문서만 보고 실행해 보니, 8쌍 중 3쌍은 끝까지 실행하지 못했다. 내가 이해한 것과 다른 사람이 문서만 보고 재현할 수 있는 것은 다른 일이었다. 버그바운티에서는 그 차이가 곧 보고서의 품질이고, 취약점을 인정받느냐 마느냐를 가른다.

## 공부 계획

1. **웹 기초와 취약점 유형**: 드림핵 웹 해킹 과정과 PortSwigger Web Security Academy로 주요 취약점의 원리와 실습을 익힌다.
2. **보고서 형식으로 기록하기**: 워게임을 풀 때도 플래그만 적지 않고, 재현 방법, 영향, 수정 제안을 갖춘 보고서 형식으로 정리하는 연습을 한다.
3. **클라우드 관점 더하기**: SSRF를 통한 클라우드 메타데이터 접근이나 잘못 설정된 스토리지처럼, 클라우드 환경에서 자주 나오는 취약점을 공부한다.
4. **실제 프로그램 참여**: 규칙과 범위를 지키며 HSPACE HVE 같은 프로그램에 참여해 본다.
